## 3. Why the probe hung (fixed)

The dump showed the first lane waiting in the signer pool's `closePage` → `browser.Session.Close` for **36 minutes**, and the page's event pump waiting in `renderer.handle` for Chromium's answer to `Network.getRequestPostData` (a request with post data on the For You page). Chromium never answered. `Close` waited for the pump before cancelling the pump's context, and the pump's call waited on that context: neither could move.

The same code runs in the crawler's signer (`tks-crawler` with `tt.signer.mode: browser`), so a crawler could have frozen the same way. Fixed in shared code, each with a test (none needs Chromium):
- the pump's post-data call has a 2 s limit (`postDataTimeout`), so an event can never hold the pump;
- `Session.Close` cancels the pump's call first and waits at most 5 s for it, then stops the browser anyway;
- the signer pool gives up closing a page after `CloseTimeout` (15 s), counts it as `stuck` in `tks_signer_page_closes_total` and signs on a new page;
- the probe bounds every call, its signature included, at 3 minutes (`callDeadline`).

On the old code the two browser tests never finish; on the new code they pass in 11 s.
