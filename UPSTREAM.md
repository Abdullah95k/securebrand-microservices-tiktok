# Upstream: igs and fbs

This repository (tks, the TikTok account scraper) owns a copy of the code of igs, the Instagram scraper, which owns a copy of the code of fbs, the Facebook page scraper. The decision and its reasons are in [ADR 0006](docs/tiktok/adr/0006-tks-code-organisation.md). tks work never changes igs's or fbs's repositories.

- **Upstream repositories:** igs, [`Abdullah95k/securebrand-microservices-igs`](https://github.com/Abdullah95k/securebrand-microservices-igs); fbs, [`Abdullah95k/securebrand-microservices`](https://github.com/Abdullah95k/securebrand-microservices).
- **Copied from:** igs `9463b91` (main, 2026-10-31), with its full history, merged into tks's `main` (`git merge --allow-unrelated-histories`), so `git blame` reaches back through igs into fbs (igs was copied from fbs at `f1377a9`).
- **Seed changes:** the Go module renamed to `github.com/abdullah95k/securebrand-microservices-tiktok` (protobuf code regenerated); the Instagram-only code removed (`internal/ig`, `internal/fakeig`, `cmd/igs-spike`, `configs/ig`, `docs/instagram`, `docs/runbooks/igs-probe.md`, the `igs-probe*` and `igs-spike-bin` Makefile targets, `phase0/ig-profiles.example.txt`); igs's README moved to [`docs/fbs-readme.md`](docs/fbs-readme.md). The copied Facebook code stays as the regression net of the copied pipeline until tks's own suites replace it (ADR 0006 §1).
- **Names on shared infrastructure** were renamed from igs's to tks's in M1b (`tks:` Valkey keys, locks `4_400_*` and `tks:*`, groups `tks-*`, header `tks-type`, API keys `tks_…`, buckets `tks-media`/`tks-raw`, metrics `tks_` with `tks_tt_*` for the platform series, alerts `Tks…`, env `TKS_`). **The copied pipeline's Kafka topics are still fbs's** (`fb.*.v1`, `fbs.task.*`) for the copied Facebook code, which runs only in tests (on random topic prefixes). M3 added tks's own topics (`tt.*.v1`, `tks.task.*`, `tks.persist.dlq`; `configs/tt/topics.yaml`, `internal/tt/topics`), which tks's binaries use from M5; the copied pipeline still does not run on shared Kafka (ADR 0006 §5). M3 also renamed the Schema Registry check subjects, which M1b missed (`igs-check-` to `tks-check-`). The probe uses none of it.

To port an igs change: `git remote add igs https://github.com/Abdullah95k/securebrand-microservices-igs`, `git fetch igs`, then `git cherry-pick <sha>` while the paths still match, or port it by hand. Record it below either way. Fetching is read-only; never push to igs's or fbs's repositories.

A cherry-picked change conflicts on any import line it touches, because the module paths differ. Resolve those by keeping this repository's paths, then run `go build ./...`; if it adds or changes a `.proto` file, run `buf generate` afterwards.

**How M2b adapted fbs's code** (each with its test):
- **Names:** fbs's new names became tks's: the retry relay's group, the lag groups (`tks-crawler-`, `tks-`), the media and raw lifecycle rule ids, the test database claim key (`tks:testenv:db:N`); the post incomplete mark's Valkey key (`pi:`) takes tks's `tks:` prefix like every other key.
- **Migrations** `00005`–`00007` of fbs are tks's `00007_erasure_retries`, `00008_media_author_key` and `00009_media_source_expired` (tks's `00005` and `00006` are its registry routes and method).
- **The page-load gate** came along: it is woven through the shared proxy pool, session loader and crawl worker. fbs's numbers (one page load per exit per 2 min, backoff 15 min to 2 h) are the default for the copied pipeline; **the probe turns it off** (`cmd/tks-spike`), as fbs's spike does, because it paces itself. tks sets its own numbers with the `tt:` section (M3, M5).
- **Unavailable pages:** fbs's loader calls Facebook's `htmlx.NamesNothing`; tks's shared loader asks the platform through a new hook, `session.Hooks.Unavailable`, which `internal/fb/client` implements with fbs's rule (tested there).
- **Dead-letter replays:** fbs marks a replayed record with a header the worker reads; tks keeps M2's `stage.Replayer` (done mark cleared, budget reset, job reopened), which now also resets `waits`; fbs's lifecycle test replays through it.
- **Persister:** tks's quarantine (M2) is kept. With NUL characters now stripped, such records are written rather than set aside; the quarantine test makes Postgres refuse with a trigger instead. fbs's tests that call its `flushSkipping` were trimmed to their writer parts (the consumer's bisection is tested by `TestBadRecordsAreSetAside`).

**Not ported:** Facebook-only fixes (parsers, `internal/fb/htmlx` beyond `NamesNothing`, the pilot and its Compose and Makefile targets, the Phase 0 report and dry run, the fixture scrubber, the release workflow). fbs `8711934` (after `b50b4a7`: comment authors kept for good by default, `privacy.retention.authors_inactive_days: 0`) is a retention choice, left for tks's privacy settings in M6 (ADR 0007 §6).

**How M9a adapted fbs's code:** a saved identity keeps tks's `session.Tokens` (the page's values, `device_id` and the rest: `internal/tt/client` `PageTokens`) and its own fingerprint profile, resumed only if that profile is still in `tt.fingerprint_profiles`; the store's keys take tks's `tks:` prefix; only tks's crawler (`internal/tt/app`) is wired to the store (not the canary, and not the copied Facebook crawler, which goes in M9). **Not ported:** fbs's `identity_max_requests` of 1500–3000 (`2dfca99`: Facebook walled page loads; TikTok did not in C2, C3 or C4, so tks keeps 400–800 until the canary says otherwise), the mentions, keyword discovery and search stages (Facebook's; tks has its own discovery), the `search` routing class, the pilot's health check, fbs's `configs/topics.yaml` (the copied pipeline's).

## The copied Facebook code removed (M9c2, 2026-11-06)

tks's own suites (`internal/tt/...`: the stages, the e2e, chaos, load and soak tests against `fakett`) now cover the pipeline, so the Facebook pipeline copied from igs at the seed is gone: fbs's binaries (`cmd/fbs-*`, `cmd/fbctl`, `cmd/fakefb`), `internal/fb`, `internal/fakefb`, the Facebook e2e suite (`internal/e2e`), `internal/{api,dispatch,registrysync,replay,spike,pilot,fixtures,gdpr,topics}`, `internal/crawl/{stage,emit,task,shadow}`, `internal/app`'s crawler, fbs's schema (`migrations/*.sql`, `store.Migrate*`), `testdata/fb`, `configs/topics.yaml`, fbs's Phase 0 kit (`phase0/dryrun*`, `pages.example.csv`, `make phase0*`, `spike-report`, `spike-bin`, `golden`, `fixtures`). fbs's runbooks moved to [`docs/fbs-reference/runbooks/`](docs/fbs-reference/runbooks/). No Facebook topic, schema or endpoint was used by anyone but this copy (no tks binary ran the Facebook pipeline since M9b2's chart).

**What stays shared, pruned to what tks uses:** `internal/app` (`KafkaClient`, `OpenRedis`), `internal/scheduler` (`Every`, `LagGauges`), `internal/persist` (the consumer with a schema's `Sink`, its quarantine and bisection, `StripNUL`, `JSONBSafe`), `internal/media` (`RawLifecycle` only: tks sets no media TTL, D5), `internal/store` (partition maintenance for `store.Tables`), `internal/crawl/{jobs,checkpoint,lanes,rawsink}` (all used by `internal/tt`), `internal/testenv` (`Postgres` is now an empty database: tks's tests migrate schema tt themselves). Their tests that ran on fbs's schema now run on their own tables (`TestBadRecordsAreSetAside` on a stub sink, `internal/store`'s partition tests, the Schema Registry test on tks's `tt.v1` contract).

**Kept on purpose:** `api/proto/securebrand/{fb,fbs}` and their generated Go, as fbs's frozen contracts for `api/proto/contract_test.go`: a task of fbs's on a tks topic, or tks's on fbs's, decodes with an unknown kind and no scope and is dead-lettered, which matters while staging shares fbs's Kafka (D6). `configs/default.yaml`'s Facebook-named sections stay (`fb.proxy` holds the proxy tiers `tks-spike` reads from the owner's `phase0/proxies.yaml`; renaming it would break that file); `configs/queries.seed.yaml` stays with them (the `fb.registry_seed` default and the shared `registry` package's tests read it).

**Porting from now on:** fbs or igs fixes to the removed packages have no tks path to cherry-pick onto; port them by hand into tks's own copies (the table above maps each to its source).
